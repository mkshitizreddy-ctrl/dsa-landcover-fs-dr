DSA PROJECT: GRAPH-BASED FEATURE SELECTION AND DIMENSIONALITY REDUCTION
=======================================================================

This file explains the code: what each file does, what each function does,
and how the parts are used. The code itself carries no comments.


-----------------------------------------------------------------------
HOW TO USE THE CODE
-----------------------------------------------------------------------

Every experiment is a function. No script takes command-line arguments;
every setting is a function parameter with a default value.

The graphical interface is a Streamlit app. Start it from the repository
root and open http://localhost:8501 in a browser:

    streamlit run app/Home.py

The app calls the functions described in this file (see STREAMLIT APP
below). They can also be called from Python in the repository root:

    import sys
    sys.path[:0] = ["src", "scripts"]
    from run_selection import run_selection
    print(run_selection())

Parameters that many functions share:
  show   receives progress messages. It is print by default; the app
         passes its own display function.
  save   whether results are written to results/. Where saving would
         overwrite results that are already stored, the default is False.
  seed   random seed, so every run can be repeated exactly.

Two functions use a held-out test set and refuse to run a second time, so
each test set is used only once: run_pso_final_test (Landsat sat.tst) and
run_final_test (pcap test hashes).

Tests: python -m pytest tests/ -q   (233 tests)

Folders:
  app/       the Streamlit app (Home.py, pages/, assets/)
  src/       the algorithms and the shared modules
  scripts/   one function per experiment, built on the modules in src/
  tests/     unit tests; each algorithm is checked against a standard library
  results/   saved outputs of every experiment
  archive/   earlier versions, kept for the project history
  data/      Landsat files and the pcap splits (pcap.csv itself is not stored)
  report/    written reports

-----------------------------------------------------------------------
HOW THE THREE STUDIES LINK
-----------------------------------------------------------------------

Study 1 writes the core data structures and algorithms from scratch (heap,
merge sort, mutual information, graph search, Union-Find, KD-tree, kNN,
PCA) and uses them to remove redundant features from the Landsat data.

Study 2 uses ten metaheuristics (Mealpy) in two ways: to choose the
settings of the Study 1 pipeline (the correlation threshold t and the
number of PCA components k), and to select features directly.

The malware family study applies the same steps (scaling, dimensionality
reduction, classification and metaheuristic search) to a much larger
dataset. Every configuration is scored once, so the study can also measure
how often each metaheuristic finds the true best configuration. Finally, the
Study 1 selection (mutual information, correlation graph, heap + BFS) runs on
the same pcap data and folds, so selection and extraction (PCA, KernelPCA,
LDA) are compared directly, in cross-validation and on the held-out test set.


-----------------------------------------------------------------------
STUDY 1: DATA STRUCTURES AND ALGORITHMS WRITTEN FROM SCRATCH
-----------------------------------------------------------------------

These modules carry the project's own algorithms. Each is checked against a
standard library in the tests (heapq, sorted, scikit-learn, scipy, numpy).

How they link:
  mi.py ranks features by relevance -> graph.py links redundant features ->
  selection.py keeps the most relevant feature of each linked group, using
  heap.py (and unionfind.py or sorting.py in the variants) -> pca.py can
  reduce the kept features further -> knn.py classifies with kdtree.py.


src/heap.py
-----------
IndexedMaxHeap: a max-heap of item ids 0..n-1, each with a numeric key.
`pos` records where each id sits in the heap array, so a key can be found
and changed in O(1) before the heap is repaired.
  push(i, key)    add an id, O(log n)
  pop()           remove and return the id with the largest key, O(log n)
  peek()          look at the largest without removing it, O(1)
  update(i, key)  change an id's key and move it up or down, O(log n)
  build(keys)     build a heap from all keys at once, bottom-up, O(n)
  _above(a, b)    True when id a belongs above id b: a larger key, or an
                  equal key and a smaller id. Equal keys therefore always
                  pop in increasing id order, so the result never depends
                  on the heap's internal layout
  _up, _down      move an item towards the root or the leaves
  _swap           swap two items and update their recorded positions


src/sorting.py
--------------
merge_sort(a, key, reverse)
  Stable merge sort, O(n log n). It splits the list in half, sorts each half
  and merges them. Items with equal keys keep their original order.


src/mi.py
---------
Mutual information between a feature and the class label, in nats.
  discretize(x, bins, tol)   equal-width bins numbered 0..bins-1. A value
                             that lies on a bin edge goes to the upper bin;
                             the small tolerance tol stops rounding errors
                             from moving it, so scaling a feature cannot
                             change its bins or its score
  mutual_info(xb, y)         I(X;Y) = sum p(x,y) log(p(x,y) / (p(x) p(y))),
                             from counts kept in dictionaries
  relevance_scores(X, y)     mutual information of every feature


src/graph.py
------------
Graph: undirected graph stored as an adjacency list.
  add_edge(u, v)          adds v to u's list and u to v's list. O(1).
  build_corr_graph(C, t)  one node per feature; an edge joins i and j when
                          |correlation| > t. O(d^2) for d features.
  bfs(g, s, max_depth)    breadth-first search; returns each reached node's
                          distance from s. O(V + E).
  dfs(g, s)               iterative depth-first search; returns visit order.
  components(g)           connected components, found by repeated BFS.


src/unionfind.py
----------------
UnionFind: disjoint sets with path halving and union by rank, so each
operation is close to O(1) amortised.
  find(x)       the representative of x's set
  union(a, b)   join two sets; returns False if already joined


src/selection.py
----------------
Feature selection that removes redundant features.
  select_features(scores, g)
      Main method. Puts all features in the heap by relevance. Repeatedly
      takes the most relevant remaining feature, keeps it, and drops its
      direct neighbours in the correlation graph (BFS to depth 1).
      O(d log d + E).
  select_per_component(scores, g)
      Variant: keeps the single most relevant feature of each connected
      component, found with Union-Find.
  select_naive(scores, C, t)
      Baseline for checking and timing: sorts by relevance with merge sort
      and keeps a feature only if its |correlation| with every kept feature
      is at most t. O(d^2). Gives the same result as select_features.


src/kdtree.py
-------------
KDTree: splits the points at the median of one axis per level, until at most
`leaf_size` points remain. Building sorts with merge_sort.
  query(q, k)   the k nearest points as (squared distance, index), sorted.
                A branch is skipped when the splitting plane is farther than
                the current k-th nearest point.
  _build, _search, _insert   build the tree, search it, and keep the
                             nearest list sorted


src/knn.py
----------
KNN: k-nearest-neighbour classifier on the KD-tree.
  fit(X, y)         builds the tree
  predict_one(q)    majority vote of the k nearest; a tie goes to the
                    smallest label
  predict(Q)        predict_one for every row


src/pca.py
----------
PCA from scratch.
  fit(X)  standardises each feature, builds the covariance matrix
          (O(n d^2)), then finds components one at a time by power
          iteration. After each component, deflation removes it from the
          matrix so the next one can be found. Stops when the kept
          components explain var_ratio of the variance (default 95%), or
          after max_components components.
  _top_eigenvector(C, rng)   power iteration: repeat v = Cv / |Cv| until v
                             stops changing; returns (eigenvalue, vector)
  transform(X)               projects standardised data onto the components
  explained_ratio            share of variance of each component
  fit_transform(X)           fit(X), then transform(X)

src/landsat_data.py
-------------------
Shared loading for the Landsat dataset (data/sat.trn and data/sat.tst).

-----------------------------------------------------------------------
STUDY 2: METAHEURISTIC COMPARISON (Landsat)
-----------------------------------------------------------------------

Ten Mealpy algorithms are compared on the same problems with the same
fitness-evaluation budget:
  GA, DE (evolutionary); PSO, GWO, WOA, HHO, ABC, MFO, SSA (swarm); SMA (bio)
Mealpy's SSA is the Sparrow Search Algorithm, not the Salp Swarm Algorithm.

Fitness (minimised):
  f = alpha * (1 - macro-F1 on validation rows) + (1 - alpha) * m / D
  alpha = 0.9; m = features kept (or components kept); D = all features.
Only the inner training and validation rows are used; outer folds and the
official test set never reach the fitness function.


src/meta_fs.py
--------------
Wrapper feature selection: the algorithm searches a feature mask.
Each algorithm searches the box [0, 1]^D; a position becomes a mask by
keeping the features whose value is at least 0.5 (at least one feature is
always kept). All algorithms share this encoding, so only their search rules
differ.
  ALGORITHMS, ALGORITHM_FAMILY   the 10 algorithms and their families
  MIN_POPULATION = 10            Mealpy's GA crashes below 10
  default_classifier(k_neighbors)   scikit-learn kNN (k = 5 by default)
  build_optimizer(name, epochs, population)
  decode_mask(position, threshold)
  FSObjective      the fitness function. It caches each mask's score, so a
                   mask seen again is not refitted, but every call is still
                   counted against the budget.
                   score_mask(mask) trains on the kept features and
                   returns (fitness, validation macro-F1).
  FSResult         best mask, fitness, inner F1, calls, distinct masks,
                   run time and the best fitness per iteration
                   selected_indices() gives the indices of the kept
                   features.
  make_optimizer_and_stop(...)
      With max_evaluations, every algorithm stops after the same number of
      fitness calls (algorithms make different numbers of calls per
      iteration, so an iteration budget would be unfair). Mealpy checks the
      budget at the end of an iteration, so a run can overshoot by at most
      one iteration; the real count is reported.
  run_feature_selection(name, X_train, y_train, X_valid, y_valid, ...)


src/meta_tune.py
----------------
Uses the algorithms to choose the settings of our own pipeline:
  threshold t    for heap + BFS selection (graph.py, selection.py)
  components k   for PCA (pca.py)
Modes: "threshold" (t only), "components" (k only), "joint" (t and k).

k is searched as a fraction q in [0, 1] and decoded as k = ceil(q * m),
where m is the number of selected features, so k <= m always holds.

The selected subset only changes when t passes one of the observed
correlation values, so every possible outcome can be listed. grid_search
does this and gives the true optimum, which the algorithms are scored
against.
  decode_k(k_frac, m)
  PipelineObjective   the fitness function, with three caches (dictionaries):
                      threshold -> subset, subset -> PCA, (subset, k) -> score.
                      Our PCA is fitted once per subset with all components;
                      each k takes the first k.
      subset_for(t), pca_projection(S), evaluate(S, k, use_pca),
      decode(position), bounds()
  TuneResult, make_result(...)
  run_tuning(name, ..., mode, max_evaluations, ...)   one algorithm run
  grid_search(..., mode)                              the exact optimum


scripts/run_mh_comparison.py
----------------------------
The full comparison with nested cross-validation.

Tasks:
  fs           search a feature mask (meta_fs)
  threshold    choose t (meta_tune)
  components   choose k (meta_tune)
  joint        choose t and k together (meta_tune)

For each outer fold (stratified 5-fold over the training file):
  1. The outer-training rows are split into inner training and validation
     rows; the scaler is fitted on inner training rows.
  2. Every algorithm and seed searches with the same budget. Tuning tasks
     also run grid_search for the true optimum.
  3. The result is evaluated on the outer fold. A mask is kept as it is; a
     chosen t and k are treated as settings, and MI, the graph, heap + BFS
     and PCA are fitted again on all outer-training rows.
The official test file is never read.

  tuning_details, grid_row, search_row, fold_data, run_fold, fold_message

  run_mh_comparison(data_path, delimiter, header, target, tasks, algorithms,
                    folds, seeds, split_seed, inner_validation_fraction,
                    budget, population, alpha, k_neighbors, quick_check,
                    save, show)
      Runs the study and returns (results, convergence). Any numeric CSV
      can be used by changing data_path, delimiter, header and target.
      quick_check=True uses 2 folds, 1 seed, 3 algorithms and budget 30
      (about 30 seconds). save=True appends to results/mh_comparison_v1.csv,
      mh_convergence_v1.csv and mh_comparison_v1.log.

src/pcap_grid.py
----------------
Scores every pipeline configuration with 4-fold cross-validation.

Pipeline: median imputation -> scaler -> reduction -> classifier, all fitted
on training rows only.

Search space:
  scalers      Standard, MinMax, Normalizer (L2)
  reductions   PCA (k = 1..36), KernelPCA with RBF kernel (k = 1..36),
               LDA (k = 1..5, because 6 classes allow at most 5)
  classifiers  Random Forest (200 trees), XGBoost (200 trees, depth 6),
               Decision Tree, SVM (RBF kernel)
  total        3 x (36 + 36 + 5) x 4 = 924 configurations, 3,696 fits

Speed-ups that do not change results:
  - Each reduction is fitted once per fold and scaler with the largest k.
    A configuration with k components uses the first k columns. PCA,
    KernelPCA and LDA order their components, so this equals fitting with k
    (checked by unit tests).
  - Decision Tree and SVM use one core each, so the different k values run
    in parallel. Random Forest and XGBoost already use every core.
  - KernelPCA keeps an n x n kernel matrix, so it is fitted on at most 8,000
    training rows. All rows are then projected and the classifier still
    trains on all of them.

Results are saved after every block. If a run stops, running it again skips
what is already done.

Outputs (results/pcap_grid_v1/):
  fold_scores.csv    one row per fit, with per-class F1
  grid_summary.csv   one row per configuration, mean and SD over folds
  grid.log           progress log

Functions:
  make_scaler(name) / make_classifier(name, seed)
      Create a scaler or classifier from its short name.
  k_values(method, n_features, n_classes, max_k, quick_check)
      Component counts tried for one reduction method. quick_check uses only
      k = 2, 10 and the largest value.
  fit_reducer(method, Z_train, y_train, n_components, ...)
      Fits PCA, KernelPCA or LDA.
  transform(reducer, Z)
      Applies a fitted reducer in chunks, to keep memory low.
  evaluate(clf_name, Z_tr, y_tr, Z_va, y_va, class_ids, seed, sample_weight)
      Fits one classifier and returns accuracy, balanced accuracy, macro-F1
      and per-class F1. A failure is returned, not raised. sample_weight is
      optional (used by pcap_class_weights.py).
  score_over_k(...)
      Runs evaluate for every k, in parallel where possible.
  load_done(path) / append_rows(path, rows, fields)
      Resume support: read finished fits and append new ones.
  summarize(fold_csv, n_folds, class_names, out_csv)
      Averages the folds into grid_summary.csv, sorted by macro-F1.
  check_choices, make_logger, result_fields, score_block, block_message
      Small helpers used by run_grid.
  run_grid(data_path, splits_path, scalers, reductions, classifiers, max_k,
           kpca_max_train, jobs, seed, quick_check, out_dir, show)
      Runs the whole grid and returns the summary table. quick_check=True
      runs fold 1 with three k values (about 2.5 minutes) and writes to
      results/pcap_grid_quick_check/. `show` receives progress messages.
  best_per(summary, column, metric)
      The best configuration for each scaler, reduction or classifier.


src/pcap_mh_search.py

-----------------------------------------------------------------------
STATISTICAL TESTS
-----------------------------------------------------------------------

Checks whether the differences between the metaheuristics are real or
could come from chance. Only saved result files are read; nothing is
retrained, and the test sets are not touched.

Which test, and why:
  Landsat (results/mh_comparison_v1.csv): every algorithm ran on the same
  5 outer folds with the same 3 seeds, so the 15 runs are paired. Each run
  is a block; the algorithms are ranked within each block (1 = best).
    Friedman test        do the algorithms differ at all?
    Nemenyi test         which pairs differ? Two algorithms differ when
                         their average ranks are further apart than the
                         critical difference
                         CD = q * sqrt(k (k + 1) / (6 N)),
                         k algorithms, N blocks, q from the studentized
                         range distribution. For k = 10, N = 15: CD = 3.50.
  pcap (results/pcap_mh_v1/runs.csv for the grid, results/pcap_fs_search_v1/
  runs.csv for the selection settings): each algorithm ran 20 times with
  its own seeds on one fixed search space, so runs are independent, not
  paired.
    Kruskal-Wallis test  do the 11 methods (10 algorithms and random
                         search) differ at all, at each budget?
    Mann-Whitney U test  each algorithm against random search, two-sided,
                         on the best F1 each run found
    Fisher's exact test  each algorithm against random search on how many
                         of its 20 runs hit the best configuration
                         (2 x 2 table: hits and misses of each)
    Holm correction      for testing ten algorithms at once

Findings:
  Landsat: the algorithms differ for feature selection (p = 0.0001) and for
  tuning t and k together (p = 0.002), not for t alone (p = 0.07) or k alone
  (p = 0.73). For feature selection PSO has the best average rank (3.73),
  but only SMA differs significantly from the top six.
  pcap: no algorithm finds a significantly better F1 than random search at
  any budget; SMA always, and HHO, WOA, MFO, GA and DE at larger budgets,
  are significantly worse. This concerns the F1 reached.
  Hitting the exact best: on the grid at budget 400 GWO hit it in 16 of 20
  runs and random search in 8 of 20, not significant after the Holm
  correction (p = 0.022, adjusted 0.22). Only SSA on the selection settings
  at budget 400 hits it significantly more often (13 against 2 of 20,
  adjusted p = 0.008).

  landsat_friedman(path, score_column, tasks)
      Friedman test for each task, with the best algorithm by average rank.
  landsat_nemenyi(task, path, score_column, alpha)
      Nemenyi pairs for one task.
  landsat_rank_table(tasks, path, score_column, alpha)
      Average rank and mean score of every algorithm for each task, with the
      CD; the input of the critical-difference diagrams.

Functions, independent runs (pcap):
  holm_adjust(p_values)
      Holm's step-down correction, written out: sort the p-values, multiply
      the i-th smallest by (m - i + 1), keep the results non-decreasing and
      at most 1, and put them back in the original order.
  kruskal_test(groups)
      scipy's Kruskal-Wallis test on {algorithm: scores}; at least three
      groups.
  compare_with_baseline(groups, baseline, alpha)
      Each algorithm against the baseline (RANDOM) with a Mann-Whitney U
      test; Holm-adjusted p-values; significant when below alpha. Sorted by
      the difference in mean, best first.
  pcap_runs(space, path)
      The saved runs of "grid" or "selection".
  pcap_groups(runs, budget, score_column)
      {algorithm: best F1 of each run} at one budget.
  pcap_kruskal(space, path, score_column)
      Kruskal-Wallis test at every budget, with the best method by mean.
  pcap_against_random(space, budget, path, score_column, alpha)
      compare_with_baseline at one budget.
  fisher_against_baseline(hits, runs, baseline, alpha)
      {algorithm: hits} and {algorithm: runs} -> each algorithm against the
      baseline with scipy's two-sided Fisher's exact test on the 2 x 2 table
      of hits and misses; Holm-adjusted p-values; sorted by the difference
      in hit rate, best first.
  pcap_hit_rates(space, budget, path, hit_column, alpha)
      fisher_against_baseline on the hit_best column of the saved runs at
      one budget.

Saving and figures:
  run_statistical_tests(save, out_dir, alpha, show)
      Runs everything above and returns the tables. save=True writes
      results/stats_v1/: landsat_friedman.csv, landsat_ranks.csv,
      landsat_nemenyi.csv, pcap_kruskal.csv, pcap_vs_random.csv,
      pcap_hit_rates.csv.
  cd_groups(ranks, cd)
      Which algorithms to join with a bar: walks through the sorted ranks,
      extends each group while it stays within the CD, and skips a group
      that lies inside an earlier one. Returns (first, last) positions.
  plot_critical_difference(ranks, cd, title)
      One critical-difference diagram: the rank axis, every algorithm at its
      average rank, a bar joining algorithms that are not significantly
      different, and a scale bar showing the CD. Returns the figure.
  save_cd_diagrams(ranks_path, out_dir, show)
      One PNG per Landsat task: results/stats_v1/cd_landsat_<task>.png.

-----------------------------------------------------------------------
SAMPLE-LEVEL CLASSIFICATION
-----------------------------------------------------------------------

Classifies whole malware samples instead of single packets. All packets
of one Hash come from one sample of one family, so they are summarised
into one row per Hash and the family is predicted for that row. Uses
data/pcap.csv (not on GitHub) and the saved split data/pcap_splits.npz,
so the development and test hashes and the 4 cross-validation folds are
the same as in the packet-level study.

Samples:
  Each Hash becomes one row: the mean, standard deviation, minimum and
  maximum of each of the 36 features, and its number of packets, giving
  145 columns. Development: 4,494 samples; test: 1,101 samples.
    family      development  test
    Benign            1,584   396
    DarkNexus            73    18
    Gafgyt                4     1
    Generic              22     7
    Mirai             2,257   538
    Unknown             554   141
  Gafgyt and Generic have very few samples, so their scores rest on very
  few cases.

Protocol:
  1. Cross-validation on the development samples, with the 4 saved folds,
     for RF, XGBoost, DT and SVM (the settings of the packet grid). Each
     model is median imputation, standard scaling and the classifier,
     fitted on the training folds only.
  2. The classifier with the best CV macro-F1 is refitted on all
     development samples and scored once on the test samples.

Results:
  Cross-validation macro-F1: RF 0.289, XGBoost 0.286, DT 0.280, SVM 0.268.
  Test (RF, 1,101 samples): macro-F1 0.309, balanced accuracy 0.316,
  accuracy 0.745. The packet-level configuration chosen by CV macro-F1
  (Normalizer + PCA (14) + DT) reached macro-F1 0.299 and accuracy 0.648
  on its test packets.
  Benign and Mirai are recognised well (recall 0.94 and 0.82); DarkNexus
  rarely (0.11), Unknown almost never (0.02), Gafgyt and Generic never.
  Whole samples score higher than packets, but the rare families still
  have too few samples to be learnt.


src/pcap_sample_level.py
------------------------
Functions:
  aggregate_by_hash(X, y, groups, stats)
      One row per Hash with the chosen statistics of every feature and the
      packet count. Missing values are skipped; a Hash with one packet gets
      a standard deviation of 0. Stops with an error if a Hash has packets
      from more than one family. Returns the table and the family of each
      row.
  hash_folds(groups, folds)
      {hash: fold} from the validation rows of the saved folds; stops if a
      hash is in two folds.
  build_sample_tables(data_path, splits_path, stats)
      Loads pcap.csv and the saved split with load_pcap and load_splits,
      aggregates the development rows and the test rows separately, checks
      that no hash is on both sides and that every development hash has a
      fold. Returns X_dev, y_dev, fold_dev, X_test, y_test, class_names.
  make_sample_model(classifier, seed)
      Median imputation, StandardScaler and make_classifier from
      pcap_grid.py.
  score_predictions(y_true, pred, class_names)
      Accuracy, balanced accuracy, macro-F1 and the F1 of every family.
  cross_validate_samples(tables, classifiers, seed, show)
      Trains on 3 folds and scores the 4th, for every fold and classifier.
      The test samples are not used.
  summarize_cv(fold_scores)
      Mean of every score per classifier and the standard deviation of
      macro-F1, best first.
  sample_counts(tables)
      Development and test samples per family.
  run_sample_cv(data_path, splits_path, classifiers, seed, save, out_dir,
                tables, show)
      Runs the cross-validation and saves cv_folds.csv, cv_summary.csv and
      samples.csv.
  choose_classifier(cv_summary)
      The classifier with the highest CV macro-F1 and that score.
  compare_with_packets(sample_result, packet_path)
      Puts the sample result next to the packet-level configuration marked
      "best overall by macro-F1" in
      results/pcap_fs_final_v1/comparison_with_grid_test.csv.
  run_sample_final_test(data_path, splits_path, cv_summary_path, out_dir,
                        packet_path, seed, tables, show)
      Refits the chosen classifier on all development samples, scores the
      test samples once and saves test_results.csv,
      test_report_sample_<classifier>.txt,
      test_confusion_sample_<classifier>.csv and
      comparison_with_packets.csv. Refuses to run if test_results.csv
      already exists, so the test samples are used only once.
