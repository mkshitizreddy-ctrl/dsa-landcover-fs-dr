DSA PROJECT: GRAPH-BASED FEATURE SELECTION AND DIMENSIONALITY REDUCTION
=======================================================================

This file explains the code: what each file does, what each function does,
and how the parts are used. The code itself carries no comments.

All functions are called from the Streamlit app. No script takes
command-line arguments; every setting is a function parameter with a
default value.


-----------------------------------------------------------------------
STUDY 1: DATA STRUCTURES AND ALGORITHMS WRITTEN FROM SCRATCH
-----------------------------------------------------------------------

These modules carry the project's own algorithms. Each is checked against a
standard library in the tests (heapq, sorted, scikit-learn, scipy, numpy).

How they link:
  mi.py ranks features by relevance -> graph.py links redundant features ->
  selection.py keeps the most relevant feature of each linked group, using
  heap.py (and unionfind.py or sorting.py in the variants) -> pca.py can
  reduce the kept features further -> knn.py classifies with kdtree.py.


src/heap.py
-----------
IndexedMaxHeap: a max-heap of item ids 0..n-1, each with a numeric key.
`pos` records where each id sits in the heap array, so a key can be found
and changed in O(1) before the heap is repaired.
  push(i, key)    add an id, O(log n)
  pop()           remove and return the id with the largest key, O(log n)
  peek()          look at the largest without removing it, O(1)
  update(i, key)  change an id's key and move it up or down, O(log n)
  build(keys)     build a heap from all keys at once, bottom-up, O(n)
  _up, _down      move an item towards the root or the leaves
  _swap           swap two items and update their recorded positions


src/sorting.py
--------------
merge_sort(a, key, reverse)
  Stable merge sort, O(n log n). It splits the list in half, sorts each half
  and merges them. Items with equal keys keep their original order.


src/mi.py
---------
Mutual information between a feature and the class label, in nats.
  discretize(x, bins)        equal-width bins numbered 0..bins-1
  mutual_info(xb, y)         I(X;Y) = sum p(x,y) log(p(x,y) / (p(x) p(y))),
                             from counts kept in dictionaries
  relevance_scores(X, y)     mutual information of every feature


src/graph.py
------------
Graph: undirected graph stored as an adjacency list.
  build_corr_graph(C, t)  one node per feature; an edge joins i and j when
                          |correlation| > t. O(d^2) for d features.
  bfs(g, s, max_depth)    breadth-first search; returns each reached node's
                          distance from s. O(V + E).
  dfs(g, s)               iterative depth-first search; returns visit order.
  components(g)           connected components, found by repeated BFS.


src/unionfind.py
----------------
UnionFind: disjoint sets with path halving and union by rank, so each
operation is close to O(1) amortised.
  find(x)       the representative of x's set
  union(a, b)   join two sets; returns False if already joined


src/selection.py
----------------
Feature selection that removes redundant features.
  select_features(scores, g)
      Main method. Puts all features in the heap by relevance. Repeatedly
      takes the most relevant remaining feature, keeps it, and drops its
      direct neighbours in the correlation graph (BFS to depth 1).
      O(d log d + E).
  select_per_component(scores, g)
      Variant: keeps the single most relevant feature of each connected
      component, found with Union-Find.
  select_naive(scores, C, t)
      Baseline for checking and timing: sorts by relevance with merge sort
      and keeps a feature only if its |correlation| with every kept feature
      is at most t. O(d^2). Gives the same result as select_features.


src/kdtree.py
-------------
KDTree: splits the points at the median of one axis per level, until at most
`leaf_size` points remain. Building sorts with merge_sort.
  query(q, k)   the k nearest points as (squared distance, index), sorted.
                A branch is skipped when the splitting plane is farther than
                the current k-th nearest point.
  _build, _search, _insert   build the tree, search it, and keep the
                             nearest list sorted


src/knn.py
----------
KNN: k-nearest-neighbour classifier on the KD-tree.
  fit(X, y)         builds the tree
  predict_one(q)    majority vote of the k nearest; a tie goes to the
                    smallest label
  predict(Q)        predict_one for every row


src/pca.py
----------
PCA from scratch.
  fit(X)  standardises each feature, builds the covariance matrix
          (O(n d^2)), then finds components one at a time by power
          iteration. After each component, deflation removes it from the
          matrix so the next one can be found. Stops when the kept
          components explain var_ratio of the variance (default 95%), or
          after max_components components.
  _top_eigenvector(C, rng)   power iteration: repeat v = Cv / |Cv| until v
                             stops changing; returns (eigenvalue, vector)
  transform(X)               projects standardised data onto the components
  explained_ratio            share of variance of each component

src/landsat_data.py
-------------------
Shared loading for the Landsat dataset (data/sat.trn and data/sat.tst).
  landsat_path(name)          the file's path; downloads it from UCI once if
                              it is missing
  load_landsat_file(name)     features (36 columns) and labels of one file
  load_landsat()              training and official test sets
  standardize(X_train, ...)   z-scores every array using the training mean
                              and standard deviation only


scripts/run_selection.py
------------------------
Compares the selection methods on the Landsat training set at thresholds
0.7, 0.8, 0.9 and 0.95.
  compare_selection_methods(X_train, y_train, thresholds)
      For each threshold: number of graph components, features kept by
      heap + BFS and by the per-component variant, and whether heap + BFS
      matches the naive method. Also returns the 5 most relevant features.
  top_features(scores, n)     the n most relevant features (merge sort)
  run_selection(thresholds)   loads and standardises the data, then runs
                              the comparison


scripts/run_fs_experiment.py
----------------------------
Accuracy of our kNN on the official test set, with all features and with
heap + BFS selection at each threshold.
  evaluate_knn(...)           fits our KNN on chosen columns; accuracy,
                              macro-F1, build and query time
  sklearn_knn_accuracy(...)   scikit-learn kNN on all features, as a check
  run_fs_experiment(thresholds, save)
      Returns the results table and the scikit-learn reference accuracy.
      save=True writes results/fs_experiment.csv.


scripts/run_pca_experiment.py
-----------------------------
Accuracy of our kNN on the official test set with six feature settings: raw,
selection only (t = 0.95, 0.9), PCA only (95% variance), and selection then
PCA.
  make_synthetic_data(seed)   a small made-up dataset for a quick check
  select_columns(...)         heap + BFS selection on training data
  prepare_features(...)       builds one setting's training and test features
  evaluate_setting(...)       fits our KNN and measures accuracy and time
  run_pca_experiment(synthetic, save)
      synthetic=True runs on the made-up data. save=True writes
      results/pca_experiment.csv.


scripts/run_complexity.py
-------------------------
Measures how the run time of graph building, heap + BFS selection and the
naive method grows with the number of features, on synthetic data with
groups of four correlated features.
  median_time(function, ...)  median time over several trials
  make_data(feature_count, rng)
  time_one_size(d, ...)       all timings for one number of features, and a
                              check that heap + BFS and naive agree
  growth_exponents(results)   k in time ~ d^k, fitted for d >= 200
  plot_runtimes(results)      log-log runtime plot
  run_complexity(feature_counts, threshold, trials, save, seed)
      Returns the table, the exponents and the plot. save=True writes
      results/complexity.csv and results/complexity.png.

Note: run_fs_experiment and run_pca_experiment use the official test set,
which earlier analyses had already used, so these numbers are reported as
project results, not as an untouched test estimate. By default they do not
overwrite the saved result files.

-----------------------------------------------------------------------
STUDY 2: METAHEURISTIC COMPARISON (Landsat)
-----------------------------------------------------------------------

Ten Mealpy algorithms are compared on the same problems with the same
fitness-evaluation budget:
  GA, DE (evolutionary); PSO, GWO, WOA, HHO, ABC, MFO, SSA (swarm); SMA (bio)
Mealpy's SSA is the Sparrow Search Algorithm, not the Salp Swarm Algorithm.

Fitness (minimised):
  f = alpha * (1 - macro-F1 on validation rows) + (1 - alpha) * m / D
  alpha = 0.9; m = features kept (or components kept); D = all features.
Only the inner training and validation rows are used; outer folds and the
official test set never reach the fitness function.


src/meta_fs.py
--------------
Wrapper feature selection: the algorithm searches a feature mask.
Each algorithm searches the box [0, 1]^D; a position becomes a mask by
keeping the features whose value is at least 0.5 (at least one feature is
always kept). All algorithms share this encoding, so only their search rules
differ.
  ALGORITHMS, ALGORITHM_FAMILY   the 10 algorithms and their families
  MIN_POPULATION = 10            Mealpy's GA crashes below 10
  build_optimizer(name, epochs, population)
  decode_mask(position, threshold)
  FSObjective      the fitness function. It caches each mask's score, so a
                   mask seen again is not refitted, but every call is still
                   counted against the budget.
  FSResult         best mask, fitness, inner F1, calls, distinct masks,
                   run time and the best fitness per iteration
  make_optimizer_and_stop(...)
      With max_evaluations, every algorithm stops after the same number of
      fitness calls (algorithms make different numbers of calls per
      iteration, so an iteration budget would be unfair). Mealpy checks the
      budget at the end of an iteration, so a run can overshoot by at most
      one iteration; the real count is reported.
  run_feature_selection(name, X_train, y_train, X_valid, y_valid, ...)


src/meta_tune.py
----------------
Uses the algorithms to choose the settings of our own pipeline:
  threshold t    for heap + BFS selection (graph.py, selection.py)
  components k   for PCA (pca.py)
Modes: "threshold" (t only), "components" (k only), "joint" (t and k).

k is searched as a fraction q in [0, 1] and decoded as k = ceil(q * m),
where m is the number of selected features, so k <= m always holds.

The selected subset only changes when t passes one of the observed
correlation values, so every possible outcome can be listed. grid_search
does this and gives the true optimum, which the algorithms are scored
against.
  decode_k(k_frac, m)
  PipelineObjective   the fitness function, with three caches (dictionaries):
                      threshold -> subset, subset -> PCA, (subset, k) -> score.
                      Our PCA is fitted once per subset with all components;
                      each k takes the first k.
      subset_for(t), pca_projection(S), evaluate(S, k, use_pca),
      decode(position), bounds()
  TuneResult, make_result(...)
  run_tuning(name, ..., mode, max_evaluations, ...)   one algorithm run
  grid_search(..., mode)                              the exact optimum


scripts/run_mh_comparison.py
----------------------------
The full comparison with nested cross-validation.

Tasks:
  fs           search a feature mask (meta_fs)
  threshold    choose t (meta_tune)
  components   choose k (meta_tune)
  joint        choose t and k together (meta_tune)

For each outer fold (stratified 5-fold over the training file):
  1. The outer-training rows are split into inner training and validation
     rows; the scaler is fitted on inner training rows.
  2. Every algorithm and seed searches with the same budget. Tuning tasks
     also run grid_search for the true optimum.
  3. The result is evaluated on the outer fold. A mask is kept as it is; a
     chosen t and k are treated as settings, and MI, the graph, heap + BFS
     and PCA are fitted again on all outer-training rows.
The official test file is never read.

Functions:
  check_settings, outer_scores, refit_pipeline, base_row, curve_rows,
  tuning_details, grid_row, search_row, fold_data, run_fold, fold_message
      the steps above, one function each
  run_mh_comparison(data_path, delimiter, header, target, tasks, algorithms,
                    folds, seeds, split_seed, inner_validation_fraction,
                    budget, population, alpha, k_neighbors, quick_check,
                    save, show)
      Runs the study and returns (results, convergence). Any numeric CSV
      can be used by changing data_path, delimiter, header and target.
      quick_check=True uses 2 folds, 1 seed, 3 algorithms and budget 30
      (about 30 seconds). save=True appends to results/mh_comparison_v1.csv,
      mh_convergence_v1.csv and mh_comparison_v1.log.

-----------------------------------------------------------------------
MALWARE FAMILY STUDY (pcap.csv)
-----------------------------------------------------------------------

Dataset: data/pcap.csv. One row is one network packet. Packets from the
same malware sample share a Hash. The label is MalwareFamily.

Order of use:
  1. src/pcap_data.py        create the splits once (create_splits)
  2. src/pcap_grid.py        score every configuration (run_grid)
  3. src/pcap_mh_search.py   search the grid with metaheuristics (run_search)
  4. src/pcap_final_test.py  evaluate the chosen configurations once (run_final_test)


src/pcap_data.py
----------------
Prepares the data and decides which rows go where. The row indices are saved
to data/pcap_splits.npz so every experiment uses exactly the same rows.

Rules:
  - Hash, Arch and MalwareFamily are not used as features.
  - Agent (1 hash) and Tsunami (3 hashes) are removed: a split grouped by
    Hash cannot place them in both training and test.
  - Infinite values become missing values. Missing values are filled later,
    inside each model pipeline, using training rows only.
  - Test set: the first fold of a stratified 5-fold split grouped by Hash
    (about 20% of rows). It is used only in the final evaluation.
  - Grid sample: at most 5 rows from each development hash.
  - Cross-validation: stratified 4-fold split grouped by Hash on the grid
    sample. Four folds, because Gafgyt has only 4 development hashes.
  - Constant columns are found on development rows only and dropped.

Functions:
  load_pcap(path, drop_classes)
      Reads and cleans the CSV. Returns PcapData: features X, class ids y,
      Hash groups, class names, and the number of removed rows.
  check_all_classes(y_part, n_classes, part_name)
      Stops with an error if a part of the data is missing any class.
  check_no_shared_groups(groups, rows_a, rows_b, part_name)
      Stops with an error if a Hash appears on both sides of a split.
  cap_rows_per_group(rows, groups, cap, seed)
      Keeps at most `cap` randomly chosen rows from each Hash.
  make_splits(data, seed, test_folds, cv_folds, rows_per_hash)
      Builds the test holdout, the grid sample and the CV folds, and checks
      every part. Returns Splits.
  save_splits(splits, path) / load_splits(path, n_rows)
      Save and load the row indices. load_splits checks that the file
      belongs to the same cleaned table.
  split_table(data, splits)
      Rows and hashes per class in each part, as a table.
  summarize(data, splits)
      The same information as readable text.
  create_splits(data_path, splits_path, rows_per_hash, cv_folds, seed)
      Runs everything above and saves data/pcap_splits.npz.


src/pcap_grid.py
----------------
Scores every pipeline configuration with 4-fold cross-validation.

Pipeline: median imputation -> scaler -> reduction -> classifier, all fitted
on training rows only.

Search space:
  scalers      Standard, MinMax, Normalizer (L2)
  reductions   PCA (k = 1..36), KernelPCA with RBF kernel (k = 1..36),
               LDA (k = 1..5, because 6 classes allow at most 5)
  classifiers  Random Forest (200 trees), XGBoost (200 trees, depth 6),
               Decision Tree, SVM (RBF kernel)
  total        3 x (36 + 36 + 5) x 4 = 924 configurations, 3,696 fits

Speed-ups that do not change results:
  - Each reduction is fitted once per fold and scaler with the largest k.
    A configuration with k components uses the first k columns. PCA,
    KernelPCA and LDA order their components, so this equals fitting with k
    (checked by unit tests).
  - Decision Tree and SVM use one core each, so the different k values run
    in parallel. Random Forest and XGBoost already use every core.
  - KernelPCA keeps an n x n kernel matrix, so it is fitted on at most 8,000
    training rows. All rows are then projected and the classifier still
    trains on all of them.

Results are saved after every block. If a run stops, running it again skips
what is already done.

Outputs (results/pcap_grid_v1/):
  fold_scores.csv    one row per fit, with per-class F1
  grid_summary.csv   one row per configuration, mean and SD over folds
  grid.log           progress log

Functions:
  make_scaler(name) / make_classifier(name, seed)
      Create a scaler or classifier from its short name.
  k_values(method, n_features, n_classes, max_k, quick_check)
      Component counts tried for one reduction method. quick_check uses only
      k = 2, 10 and the largest value.
  fit_reducer(method, Z_train, y_train, n_components, ...)
      Fits PCA, KernelPCA or LDA.
  transform(reducer, Z)
      Applies a fitted reducer in chunks, to keep memory low.
  evaluate(clf_name, Z_tr, y_tr, Z_va, y_va, class_ids, seed)
      Fits one classifier and returns accuracy, balanced accuracy, macro-F1
      and per-class F1. A failure is returned, not raised.
  score_over_k(...)
      Runs evaluate for every k, in parallel where possible.
  load_done(path) / append_rows(path, rows, fields)
      Resume support: read finished fits and append new ones.
  summarize(fold_csv, n_folds, class_names, out_csv)
      Averages the folds into grid_summary.csv, sorted by macro-F1.
  check_choices, make_logger, result_fields, score_block, block_message
      Small helpers used by run_grid.
  run_grid(data_path, splits_path, scalers, reductions, classifiers, max_k,
           kpca_max_train, jobs, seed, quick_check, out_dir, show)
      Runs the whole grid and returns the summary table. quick_check=True
      runs fold 1 with three k values (about 2.5 minutes) and writes to
      results/pcap_grid_quick_check/. `show` receives progress messages.
  best_per(summary, column, metric)
      The best configuration for each scaler, reduction or classifier.


src/pcap_mh_search.py
---------------------
Searches the 924 configurations with 10 metaheuristics (Mealpy) and with
random search as a baseline. A candidate's score is looked up from
grid_summary.csv, so no model is trained and a full run takes seconds.

Encoding: four numbers in [0, 1] become one configuration:
  scaler      = one of 3 equal parts of [0, 1]
  reduction   = one of 3 equal parts of [0, 1]
  k           = ceil(x * largest k), so 1..36, or 1..5 for LDA
  classifier  = one of 4 equal parts of [0, 1]
Fitness (minimised) = 1 - CV macro-F1.

Cost is the number of different configurations tried, because in a real
search each new configuration costs 4 model fits and a repeat costs nothing.

Functions:
  pick_option(x, options)
      Maps a number in [0, 1] to one option.
  GridSpace(table)
      Holds every configuration's score. decode(position) turns four numbers
      into a configuration; rank(cfg) gives its true rank (1 = best);
      count_within(gap) counts configurations within `gap` of the best.
  Tracker(space, near)
      The fitness function. It also records the configurations tried, the
      best score so far, and when the best (or a near-best) was found.
  run_algorithm(name, space, budget, population, seed, near)
      One run of one Mealpy algorithm with a fixed number of fitness calls.
  run_random(space, budget, seed, near)
      One run of random search with the same budget.
  p_random_hit(n_total, n_good, n_draws) / random_search_odds(space, near)
      The exact chance that random search finds the best configuration.
  summarize_runs(runs)
      Hit rates, mean rank and configurations tried per algorithm and budget.
  run_search(grid_path, algorithms, budgets, n_seeds, population, near,
             save, out_dir, show)
      Runs every algorithm for every budget and seed. Returns (runs,
      summary). save=False runs without writing files, for live use in the
      app. Outputs: results/pcap_mh_v1/runs.csv and a summary file.


src/pcap_final_test.py
----------------------
Evaluates the chosen configurations once on the held-out test set.

Chosen configurations:
  - the best overall by CV accuracy (the reference pipeline's rule)
  - the best of each classifier: C1 (RF), C2 (XGB), C3 (DT), C4 (SVM)
  - the same choices by CV macro-F1
Configurations chosen for several reasons are evaluated once.

Each is refitted on all development rows, except:
  - SVM trains on a stratified 60,000-row subsample (training time grows
    with the square of the rows).
  - KernelPCA is fitted on 8,000 rows; every row is then projected.

The function refuses to run if results already exist, so the test set is
used only once.

Outputs (results/pcap_final_v1/): test_results.csv, a classification report
and a confusion matrix per configuration, best_configuration.csv, and
best_model.joblib (the configuration with the highest CV accuracy).

Functions:
  select_configs(grid)
      Picks the configurations listed above, with the reasons for each.
  fit_config(cfg, X_train, y_train, seed, kpca_max_train, svm_max_rows)
      Fits imputer -> scaler -> reduction -> classifier. Returns the
      pipeline and the number of training rows.
  predict_chunked(pipe, X)
      Predicts in chunks, to keep memory low.
  config_tag(cfg)
      A short name such as Normalizer_PCA_k14_DT.
  save_test_outputs, evaluate_on_test, save_selected_model
      Helpers that score one configuration and save its files.
  run_final_test(data_path, splits_path, grid_path, out_dir, svm_max_rows,
                 kpca_max_train, seed, show)
      Runs the whole evaluation and returns the results table.
